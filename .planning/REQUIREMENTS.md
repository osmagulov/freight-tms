# Requirements: Freight TMS

**Defined:** 2026-03-08
**Core Value:** Диспетчер в любой момент знает где каждый борт, что везёт, сколько потратил — и может назначить новый рейс до возврата машины.

---

## v1 Requirements

### Infrastructure

- [ ] **INFRA-01**: Система развёрнута на Railway — FastAPI + PTB webhook в одном процессе, PostgreSQL addon
- [ ] **INFRA-02**: Alembic миграции запускаются до старта приложения (pre-deploy hook, не внутри startup)
- [ ] **INFRA-03**: Cloudflare R2 подключён для хранения фото чеков и документов
- [ ] **INFRA-04**: FSM-состояние ConversationHandler персистируется (PicklePersistence) — не теряется при Railway редеплое
- [ ] **INFRA-05**: Веб-панель требует авторизации (JWT, роли: dispatcher / director)

### Registration

- [ ] **REG-01**: Водитель может зарегистрироваться через /start в Telegram-боте (ФИО, телефон)
- [ ] **REG-02**: Водитель может привязать борт к своему аккаунту (по номеру/госномеру)
- [ ] **REG-03**: Диспетчер видит список зарегистрированных водителей и их бортов на веб-панели
- [ ] **REG-04**: Диспетчер может вручную создать/отредактировать запись борта (марка, модель, норма расхода л/100км)

### Expense Submission (Driver — Telegram bot)

- [ ] **EXP-01**: Водитель может зафиксировать расход топлива: литры + одометр + фото чека + название заправки
- [ ] **EXP-02**: Система валидирует одометр: новый > предыдущего и < предыдущего + 5000 км
- [ ] **EXP-03**: Водитель может подать суточные: сумма + валюта + город
- [ ] **EXP-04**: Водитель может зафиксировать штраф: фото + сумма + причина
- [ ] **EXP-05**: Водитель может зафиксировать прочие расходы (ремонт, запчасти, паром, таможня): категория + сумма + фото (опционально)
- [ ] **EXP-06**: Водитель видит сводку своих расходов в боте: ожидают одобрения / одобрены / итого за рейс
- [ ] **EXP-07**: Расходы можно записывать в нескольких валютах (KZT, RUB, EUR, USD) — сумма + валюта + курс на момент подачи
- [ ] **EXP-08**: Система предотвращает дублирование расходов (идемпотентный ключ по водителю + тип + сумма + время с точностью до минуты)

### Expense Management (Dispatcher — web)

- [ ] **EAPPR-01**: Диспетчер видит очередь расходов на одобрение: водитель, тип, сумма, фото
- [ ] **EAPPR-02**: Диспетчер может одобрить или отклонить расход с комментарием (HTMX inline, без перезагрузки страницы)
- [ ] **EAPPR-03**: Водитель получает уведомление в бот при одобрении/отклонении расхода

### Trip Management

- [ ] **TRIP-01**: Диспетчер может создать рейс: борт, водитель, маршрут (откуда → куда), груз, клиент, даты
- [ ] **TRIP-02**: Водитель получает уведомление в бот о назначенном рейсе
- [ ] **TRIP-03**: Водитель может открыть рейс в боте (подтвердить выезд, стартовый одометр)
- [ ] **TRIP-04**: Водитель может прикрепить документы к рейсу через бот (CMR/накладная/договор — фото или PDF)
- [ ] **TRIP-05**: Водитель может закрыть рейс (финальный одометр, статус доставки)
- [ ] **TRIP-06**: Диспетчер видит историю рейсов по борту и по водителю (поиск, фильтры)
- [ ] **TRIP-07**: Диспетчер видит детали рейса: все расходы, документы, геолокации

### Location Tracking

- [ ] **LOC-01**: Водитель может поделиться геолокацией через кнопку в боте (Telegram native geolocation)
- [ ] **LOC-02**: Диспетчер видит карту с последними позициями всех бортов (Leaflet + OpenStreetMap)
- [ ] **LOC-03**: Карта автоматически обновляется каждые 30 секунд (HTMX polling)
- [ ] **LOC-04**: На карте отображается: госномер борта, водитель, время последней точки

### Fleet Dashboard (Dispatcher — web)

- [ ] **FLEET-01**: Диспетчер видит список всех бортов со статусом (в рейсе / свободен / техобслуживание) и последней позицией
- [ ] **FLEET-02**: Диспетчер видит текущий рейс и водителя для каждого борта в списке
- [ ] **FLEET-03**: Диспетчер видит ленту аномалий (расход топлива выше нормы) с кнопкой «ложная тревога»

### Director Dashboard (web)

- [ ] **DIR-01**: Директор видит сводку расходов: итого по категориям (топливо / суточные / штрафы / ремонт) за выбранный период
- [ ] **DIR-02**: Директор видит расходы в разрезе бортов: рейс за рейсом, с фильтрацией по периоду
- [ ] **DIR-03**: Директор может экспортировать расходы в CSV (фильтр по борту / водителю / периоду)
- [ ] **DIR-04**: Директор видит историю аномалий: борт, рейс, % превышения, статус (активна / ложная тревога / подтверждена)
- [ ] **DIR-05**: Директор видит историю расходов по конкретному водителю (для разрешения споров)

### Anomaly Detection

- [ ] **ALERT-01**: Система вычисляет фактический расход топлива (литры / км пробега) при каждой заправке
- [ ] **ALERT-02**: Система создаёт алерт если расход превышает норму борта на >20% (не 10% — слишком много ложных сигналов на горных маршрутах)
- [ ] **ALERT-03**: Алерт требует минимум 2 предыдущих заправки для первого срабатывания
- [ ] **ALERT-04**: Директор получает Telegram-уведомление при новом алерте (дайджест, не мгновенно)

## v2 Requirements

### GPS & Real-time Location

- **GPS-01**: Фоновый трекинг через SIM-карту GPS-трекера (не Telegram)
- **GPS-02**: Telegram Live Location (автоматическое обновление на 1-8 часов)

### Advanced Analytics

- **ANLYT-01**: Бенчмаркинг маршрутов (средний расход на маршруте по истории)
- **ANLYT-02**: Автоматический курс валют при подаче расходов (FX API)
- **ANLYT-03**: Таблица суточных по странам маршрута (KZ, RU, TR, GE, EU)
- **ANLYT-04**: Леджер выплат водителю (баланс одобренных расходов)

### Integrations

- **INT-01**: Интеграция с 1С/ERP для выгрузки расходов
- **INT-02**: Выставление счетов клиентам
- **INT-03**: Интеграция с топливными картами

## Out of Scope

| Feature | Reason |
|---------|--------|
| Мобильное приложение | Водители в Telegram — переучивать не нужно |
| GPS-трекер (SIM) | V2 — MVP только ручная геолокация |
| Интеграция с 1С/ERP | V2 — слишком сложно для MVP |
| Финансовый модуль (счета клиентам) | V2 — другой продукт |
| Мультиязычность | Все пользователи говорят по-русски |
| Автоматические курсы валют | V2 — в MVP диспетчер вводит курс вручную |
| Роутинг / планирование маршрутов | V2 — слишком специализированно для MVP |
| Уведомления клиентам о статусе груза | V2 — customer portal |
| Celery + Redis | Заменяется APScheduler — экономит Railway сервис |
| React/Vue frontend | Jinja2 + HTMX достаточно для 5 внутренних пользователей |
