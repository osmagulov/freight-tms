# Freight TMS

## What This Is

Система управления грузоперевозками для парка 100+ водителей и 200+ фур на международных маршрутах (CN↔KZ, KZ↔RU, Центральная Азия, Турция, Грузия). Водители работают через Telegram-бот или PWA на телефоне, диспетчеры и директор — через веб-панель.

## Core Value

Диспетчер в любой момент знает где каждый борт, что везёт, сколько потратил — и может назначить новый рейс до возврата машины.

### Active

**Водители (Мобильное PWA-приложение + Telegram-бот):**
- [x] Водитель регистрируется и привязывает борт

- [x] Обертка PWA мобильного приложения (Альтернатива телеграм-боту, /app/login — вход по телефону+пароль)

**Диспетчер (веб-панель):**

- [x] Назначить рейс борту (маршрут, груз, клиент, документы)
- [x] История рейсов по борту/водителю
- [x] Просмотр расходов по рейсу

**Директор (веб-панель):**

## Context

- Водители привыкли к Telegram, переучивать не нужно — оба канала работают
- Диспетчеры работают с компьютера в офисе
- Маршруты международные: важны таможенные документы (CMR, накладная, договор)
- Текущий инструмент: WhatsApp/Telegram — всё в голове и переписке

## Constraints

- **Tech**: Python ecosystem (FastAPI + python-telegram-bot) — команда знает Python
- **Database**: PostgreSQL — масштаб 100+ водителей требует реляционной БД
- **Deployment**: Railway — уже используется
- **Scale**: 100+ водителей, 200+ фур — архитектура должна выдерживать одновременные запросы

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------| 
| Telegram-бот для водителей + PWA | Водители в Telegram; PWA — обход блокировок | ✅ Оба канала работают |
| FastAPI + PostgreSQL (не Django) | Легче интегрировать с ботом, гибче | ✅ Работает |
| Геолокация через бот/PWA (не GPS-трекер) | MVP — быстрее, дешевле; трекер V2 | ✅ Кнопка в PWA и боте |
| APScheduler (не Celery+Redis) | Экономия Railway-сервиса | ✅ Аномалии hourly in-process |
| Статические FX-курсы | Скорость MVP; live API — V2 | ✅ Реализовано в PWA и боте |
